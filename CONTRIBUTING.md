# Contribuciones a AudioScribe 🎙️

¡Gracias por tu interés en contribuir a **AudioScribe**! Apreciamos cualquier contribución, ya sea reportando errores (*bugs*), sugiriendo nuevas funcionalidades o enviando mejoras de código (*Pull Requests*).

---

## 📋 ¿Cómo puedo contribuir?

### 1. Reportar Errores (Bugs)
Antes de crear un *issue*, por favor verifica:
- Que estés utilizando la versión más reciente del repositorio.
- Que no exista ya un *issue* abierto reportando el mismo problema.
- Al reportar, incluye:
  - Sistema operativo y versión de Python.
  - Pasos exactos para reproducir el fallo.
  - Mensajes de error o capturas de pantalla si es pertinente.

### 2. Proponer Mejoras o Nuevas Funcionalidades
- Abre un *Issue* describiendo la idea, su caso de uso y cómo mejoraría la experiencia del usuario.

### 3. Enviar un Pull Request (PR)
1. Haz un **Fork** de este repositorio.
2. Crea una rama descriptiva para tu cambio (`git checkout -b feature/nueva-funcionalidad` o `git checkout -b fix/error-transcripcion`).
3. Realiza tus cambios asegurándote de seguir las directrices de estilo (PEP 8 para Python, nombres semánticos para HTML/CSS/JS).
4. Verifica que el servidor inicie correctamente y que todas las herramientas funcionen sin errores.
5. Haz commit con mensajes claros y concisos.
6. Haz push a tu rama (`git push origin feature/nueva-funcionalidad`).
7. Abre un **Pull Request** explicando detalladamente tus modificaciones.

---

## 🎨 Estándares de Código
- **Python**: Estricto cumplimiento de PEP 8, modularidad y manejo adecuado de excepciones.
- **Frontend**: Mantener el diseño basado en Glassmorphism, CSS con variables unificadas y JavaScript moderno sin dependencias externas pesadas.
- **Documentación**: Mantener actualizados los comentarios y el archivo `README.md` si se introducen nuevos endpoints o parámetros.
